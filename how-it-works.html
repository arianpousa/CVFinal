How it works

Everything happens inside your browser. Your photos are never uploaded, and there is no server and no account.

The four steps

  1. Find the page. The app makes a gray copy of your photo, softens it slightly so paper texture doesn't count as an edge, and traces strong edges with the Canny edge detector. It then looks for the largest outline that simplifies to four corners. That's the page. If the edges are faint, it tries again by separating bright paper from a darker desk. If nothing fits, the corners start at the photo's edges and you drag them into place.
  2. Flatten it. The four corners are stretched to a rectangle with a perspective warp, so a photo taken at an angle looks scanned flat. The app also works out the page's real shape from the corners, so a letter photographed at a steep angle still comes out letter-shaped, not squashed.
  3. Make it crisp. Adaptive thresholding decides black or white for each small neighbourhood separately, so a shadow across the page doesn't turn into a black blotch. You can also keep it in Color or Gray.
  4. Save it. The original photo and the cleaned scan are saved together, with a name and the date, in your browser's own database.

OpenCV.js

OpenCV is a large, well-known computer-vision library written in C++. OpenCV.js is the same library rebuilt so it can run in a web page. This app uses the official 4.10.0 build, stored with the site as one 10 MB file (about 3.4 MB once the server compresses it). Your browser downloads it once and then keeps it in its cache.

WebAssembly

WebAssembly is a compact binary format that browsers run at close to native speed. OpenCV.js is C++ compiled to WebAssembly, so the image maths runs much faster than ordinary JavaScript would.

WebAssembly has its own block of memory that JavaScript's automatic clean-up can't see. Every image OpenCV.js works on (a cv.Mat) lives there, so the app deletes each one as soon as it's done. In the project's tests, that memory stayed at 128 MiB after 420 scans in a row, so nothing leaks.

A Web Worker, so the page never freezes

A Web Worker is a background thread. OpenCV.js loads once inside it, and every scan runs there, so buttons, scrolling and the corner handles stay responsive while a scan is processed. Images are handed to the worker as transferable objects, which moves them without copying. If the worker ever gets stuck, the app stops it and starts a fresh one.

IndexedDB: your library stays on your device

IndexedDB is a database built into every modern browser. The app keeps a database called docscanner with four parts: scans (name, date, size, style), blobs (the original photo, the scan and a thumbnail, stored as image files), settings and history. Each save is one all-or-nothing step, so a scan is never half-saved, and the library is still there after you refresh or restart the browser.

The database has a version number. When a future version changes its layout and you have the app open in two tabs, the old tab steps aside for the update. If a tab can't, the app asks you to close it.

Troubleshooting

What you seeWhat to do
"Loading scanner…" never turns into "Ready"Check your connection and reload with Ctrl+Shift+R. The first visit downloads about 3.4 MB. If it still fails, press Try again in the banner.
"Close other tabs of this app to finish updating."Another tab has an older copy of the database open. Close the other tabs, and this one continues on its own.
"Couldn't find the page edges."Drag the four corners onto the page corners, or focus a corner and use the arrow keys. A darker background behind the page helps.
"Storage is full."Delete a few scans from the Library.
Anything else seems stuckUse Reset app data at the bottom of the scanner page. It deletes every scan and setting stored in this browser and reloads the app.

Looking inside with Chrome DevTools (Windows): press F12 (or Ctrl+Shift+I), open the Application tab, then Storage → IndexedDB → docscanner. Pick a store, such as scans, to see your records, and press the refresh button in that panel after saving a new scan. From there you can delete single entries, clear a store or delete the database (Chrome DevTools IndexedDB guide). Application → Storage → Clear site data removes everything at once. The Console tab shows errors, and Sources → Threads lists the scanner's worker.
